# 乐谱审校需求

用户：乐团资料员、音乐出版社编辑、器乐教师。

主流程：导入 MusicXML/MXL → 确认原谱渲染 → 选择声部和 A4/连续版式 → 选择声部与小节添加批注/核对状态 → 保存 → 重新打开 → 导出 SVG、原件、批注报告。

原始文件必须逐字节保留；审阅位置、声部筛选、比例、版式、批注一起持久化。导入先安全解析并试渲染，再替换当前工作；任何失败保持当前数据。覆盖未保存修改、删除项目及删除批注需明确确认。保存以 revision 检查并发冲突。

支持 UTF-8 score-partwise；文件 200 KB、XML 180 KB、12 声部、每声部 200 小节、4000 音符/休止符、100 条批注。拒绝外部实体/资源，MXL 另检查目录路径、条目与实际解压长度。文件限制和不支持的 DTD 在 README 与错误信息中明确说明。

仅实现渲染与审校，不承诺音符编辑、完整制谱、播放器或任意 MusicXML 扩展。无 AI/外部服务依赖。原创建谱示例只用于展示。

验收：真实引擎输出、XML/MXL 原件恢复、批注锚点与报告、错误恢复、保存冲突、键盘与375px、dark/reduced-motion、独立打开SVG/XML、固定模板check/test/package；导入客户端安装另行验收。

自动保存：停止输入约 700 ms 后保存，后台请求不锁编辑。未写完的空白批注、显示设置及当前小节可在刷新后恢复；不合法的业务输入显示“草稿已自动保存，待完善输入”，不会覆盖最后的合法内容。网络失败时保留本机副本，版本冲突提供恢复草稿导出与服务器版本入口。导入先验证，再创建独立项目。

当前布局：谱面为主体、右侧小节索引与审校批注；375px、暗色与减少动画偏好保持可用。

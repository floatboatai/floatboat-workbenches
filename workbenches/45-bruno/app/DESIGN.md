# Bruno 0.9.0 · 接口调试台

## 用户与主任务

使用者是调试、回归 HTTP API 的开发者与测试人员。主任务与 Bruno 桌面版一致：在集合树里选中请求 → 修改方法/URL/参数/头/正文/认证 → 选择环境 → 点「发送」→ 在响应控制台看状态、正文、断言结果和历史。结构化编辑与原生 `.bru` 源码双向自动同步，没有“更新源文件”这一步。

## 首次使用

空数据目录直接打开示例集合「订单服务 API」，默认选中 `本机/健康检查`，环境为「本机回声」。该环境的 `baseUrl` 取内置动态变量 `{{$localEcho}}`，指向工作台进程内的 127.0.0.1 回声服务，所以第一次点「发送」就能得到 200、JSON 正文和 2/2 通过的断言，不依赖任何外部服务或 Host。公开 API 示例（JSONPlaceholder）放在单独文件夹，只在用户显式发送时访问网络。

## 继续上次工作

完整工作副本（源文件、未写入的结构化编辑、无效源码、当前环境、响应历史）由共享自动保存持久化到 SQLite + IndexedDB。重开即回到上次集合与请求。秘密环境变量的值只在当前页面内存中，刷新后在环境面板重新输入；文件里只记录 `vars:secret [name]`。

## 导入恢复

左上「集合」菜单集中全部文件生命周期：新建空白集合、打开示例集合、打开已保存集合、导入 `.bru`/`bruno.json` 文件、集合文件夹、Bruno 集合 ZIP 或工程 JSON；导出原生集合 ZIP、当前 `.bru`、完整工程、恢复稿；立即保存/冲突时打开服务器版本。所有导入均创建新副本，不覆盖当前集合。

## 空间关系

- 顶栏（单行）：品牌、「集合」菜单、集合名、环境选择器 + 环境按钮、安静的保存状态。
- 左：集合树（文件夹 → 请求，方法色标与最近结果圆点），树顶「新请求」，树底「集合设置」（bruno.json、collection.bru）；文件夹内有「文件夹设置」。窄屏收为「请求列表」抽屉。
- 中上：请求名 + 方法/URL/发送 横条，紧贴请求编辑器；未定义变量、缺少的秘密值和阻止原因在发送后于横条下方与响应控制台说明，请求不发出。
- 中：请求编辑器分页 Params · Body · Headers · Auth · Vars · Assert · Docs · Bru 源。键值行均为表格（启用/名/值/删除）。
- 右：响应控制台：状态码、耗时、大小；分页 正文 · Headers · 断言 · 实际请求 · 历史。
- 失败/未知回执、阻止原因在发送按钮下方就地说明，不使用浏览器 confirm。

## 视觉

保留深石墨编辑台与琥珀色「发送」，方法色标沿用 Bruno 习惯（GET 绿、POST 琥珀、PUT 蓝、DELETE 红、PATCH 紫）。状态码 2xx 青绿、4xx 橙、5xx 红；断言通过/失败用文字 + 色块双编码。等宽字体只用于 URL、键值和正文。无营销卡片、无顶部统计。

## 窄屏（375px）

顶栏保留集合菜单、环境选择器和保存状态；集合树变为「请求」抽屉按钮；URL 横条换行为方法+URL 一行、发送一行；请求编辑器与响应控制台纵向排列，发送后自动滚到响应。分页条横向滚动，页面本身不溢出。

## 与相邻工作台的差异

Swagger UI 是规格阅读器（端点目录 + 文档）；Bruno 是可执行请求集合（树 + 编辑器 + 控制台）。React Flow 的控制台服务节点运行；这里的控制台服务单个 HTTP 交换及其历史。

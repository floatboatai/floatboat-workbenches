# API 参考台

面向需要读懂并调用 HTTP API 的开发、测试与对接人员：导入真实 OpenAPI/Swagger 规格，按端点阅读原生文档并试调，按需并排维护规格原文。

## 功能与边界（0.9.0）

- 接受 OpenAPI 3.0 / 3.1 / 3.2 与 Swagger 2.0，YAML 或 JSON。保存的模型是 `{ format, source }`：用户给出的原文与格式；预览对象总由原文解析得到。0.3.0 保存的 `{ spec }` 读取时升级为 JSON 原文。
- 绝对 servers、服务器变量、内部 `$ref`、`securitySchemes`/`securityDefinitions` 均可用。外部 `$ref` 不抓取（警告并给出行号）。原型污染键与超过 96 层嵌套被拒绝；YAML 别名展开上限 200。
- 只有语法或结构错误（无法解析、缺版本、缺 info.title、缺 paths 等）阻止应用；其它问题作为警告显示，不阻止预览。
- 源码草稿与已应用模型分开：错误草稿保存在工作副本 `extra.editorText`，刷新后恢复并重新诊断；修正后自动应用并清除草稿。
- 试调：所有常用方法。同源只允许内置示例 `/api/sample/` 与旧示例 `/api/demo/`；外部 http(s) 由 `/api/try/send` 代理，只在用户点击 Execute 时发出。默认阻止本机/私有/链路本地/保留地址，允许开关只存在于当前页面内存。代理不跟随重定向、不转发 Host/Content-Length 等连接层头，超时 30 秒、请求体 1 MB、响应 5 MB（超出截断并标注）、并发 4。凭据不持久化、不记录。
- 导入另建新规格；导出原文逐字节一致；另存为另一格式由解析结果转换。
- AI 起草返回候选，用户明确采用后才替换源码；未连接 Floatboat 时给出启动说明。

## 验收要求

真实浏览器：首次打开空数据目录完成 Authorize → POST → 201；外部代理成功/阻止/DNS 失败各自有可读原因；源码错误行号、草稿刷新恢复、修正后自动应用；延迟保存期间继续输入保留新内容；响应丢失后重试只产生一个项目；导入另建规格与导出内容校验；375 px 与 1440 px；Escape 关闭菜单并归还焦点；控制台无页面错误。功能验收与结构审查分别记录。

0.2.0 起自动保存为默认行为，完整工作副本包含未应用输入；不得把离线或仅草稿状态报告为已应用。

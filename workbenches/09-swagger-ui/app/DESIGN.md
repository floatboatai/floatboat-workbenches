# API 参考台设计（0.9.0）

## 用户与主任务

使用者是要读懂并调用一份 HTTP API 的开发者、测试与对接人员。P0 是**按端点阅读原生 Swagger 文档并试调**：从目录找到端点、看参数/模型、点 Try it out → Execute 得到真实响应。P1 是**维护规格原文**：与预览并排编辑 YAML/JSON，按行号修正诊断。P2 是文件生命周期：导入、另存、切换、恢复。

工作对象叫「接口规格」（一份 OpenAPI/Swagger 原文），不是“项目”。

## 首屏与空间关系

```
┌ 文件条：[规格] API 标题 · 版本 · OAS/格式 · 安静的保存状态 ·········· [参考|并排源码] [试调] [起草] ┐
├ 端点目录（260px） ┬ 原生 Swagger UI（主区，独立滚动）                                         ┤
│ 搜索端点           │  标题、描述、服务器选择、Authorize、标签分组、Schemas                    │
│ 标签分组·方法色块   │                                                                         │
│ 模型 / 认证 / 服务器│                                                                         │
└──────────────────┴─────────────────────────────────────────────────────────────────────────┘
```

- 主区：Swagger UI 占据剩余宽度与全部高度，iframe 内部滚动，切换模式不重建（授权值、展开状态保留）。
- 上下文：左侧端点目录按标签分组，方法色与 Swagger 色块一致；点击在文档中展开并定位，在并排模式下同时把源码跳到该操作所在行。目录底部列出模型、认证方案（「授权」打开 Swagger 的 Authorize）与服务器。
- 按需：「并排源码」在目录与文档之间打开编辑器（行号、诊断标记、诊断列表），停止输入约 0.4 秒后自动解析；没有错误时立即更新右侧预览并作为已应用模型保存，有错误时保留为源码草稿，预览停在上次有效版本。
- 主业务动作贴近对象：试调按钮就在 Swagger 的每个端点内；试调通道状态（代理、超时、阻止原因、允许本机目标）在文件条「试调」面板，被阻止时在文档底部弹出状态卡并给出允许入口。

## 首次使用

空数据目录直接打开「社区图书馆借阅 API」示例（YAML，4 个标签、12 个端点、8 个模型、Bearer 与 API Key 两种认证）。第一台服务器是工作台内置示例服务，不需要任何外部服务即可完成：浏览 → Authorize（任意令牌）→ POST 新增图书 → 201 响应。第二台服务器是示例正式域名，经服务端代理转发。

## 继续上次工作

自动保存恢复最后一份规格（含未应用的源码草稿和光标所在模式以外的状态）。「规格」菜单中的最近列表包含服务器与本机暂存的副本，标出“本机草稿”“待完善”。

## 导入与恢复

「规格」菜单：新建空白规格、打开图书馆示例、导入 .yaml/.yml/.json（保留原文与格式，另建新规格）、导出原文、另存为另一格式、下载/导入恢复稿、删除。导入文件有语法或结构错误时说明首个错误行，并可“作为源码草稿打开”继续修正。

## 视觉与密度

- 文件条与目录：冷白纸色（#f6f7f5）+ 墨蓝文字，细分隔线，没有卡片和统计块；文档区保持 Swagger 官方白底以便对照官方文档。
- 编辑器：深色代码面板（#1d2126），等宽 13px，行号槽中错误红点、警告琥珀点；诊断列表可点击跳行。
- 方法色沿用 Swagger：GET 蓝、POST 绿、PUT 橙、DELETE 红、PATCH 青、HEAD 紫、OPTIONS 深蓝。
- 外框跟随系统深色模式，文档纸面保持白色；尊重 reduced-motion。

## 窄屏（375px）

文件条压缩为「规格」+ 标题 + 「更多」；下方三段切换：目录 / 文档 / 源码，一次只显示一个区域，iframe 不卸载。目录点击后自动切换到文档并定位端点。菜单与面板为全宽对话框，Escape 关闭并把焦点还给触发按钮。

## 与相邻工作台的差异

- Bruno：以请求集合和单个请求编辑器为中心；这里以规格文档为中心，请求由规格生成。
- Mermaid：源码与图形预览；这里默认不显示源码，参考文档与端点目录优先。
- 0.8.1 的 Oasis/Circuit/glTF：同样把文件生命周期收进单一入口菜单，主对象占据首屏，不保留顶部项目选择器与新建/保存/导入按钮组。

## 结构审查（0.9.0，2026-10-29）

对照 `docs/screenshots/oasis-editor.png`、`gltf-transform.png` 与 `bruno.png` 的实际截图：

- 主区占比：1440 宽时 Swagger 文档占 1168 px（81%），目录 272 px；并排源码时目录 252 / 源码约 560 / 文档约 620，1180 px 以下并排时目录收起。0.3.0 的顶部项目选择器、新建/立即保存/AI 按钮组与侧栏导入/导出/删除按钮全部移入「规格」菜单。
- 工具位置：主业务动作（Try it out / Execute / Authorize）留在 Swagger 端点内；目录中的「填写凭据」直接打开 Authorize；试调阻止原因贴在文档底部并附允许入口。
- 文件生命周期：与 Oasis「文稿」、glTF「资产库」同为左上单一入口；与 Bruno 的常驻请求集合不同，这里集合就是规格本身的端点目录。
- 窄屏顺序：文件条 → 目录/文档/源码三段切换；目录点击自动切到文档并定位；菜单为全宽对话框。
- 空态与有内容：空白规格时目录显示“打开并排源码在 paths 下添加”，导入失败时菜单内给出首个错误行和“作为源码草稿打开”。

自查结论：结构通过（真实截图：`docs/screenshots/swagger-ui.png`，任务路径见 ACCEPTANCE.md）；最终结构状态由主线集成时确认。

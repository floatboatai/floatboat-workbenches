# 0.9.0 · 模型优化台

## 主任务
技术美术或前端开发者拿到一份真实导出的 GLB/glTF（Blender、Sketchfab、DCC 管线），要在交付 Web/实时引擎前把它变小、变快且不坏：看清它有多少绘制调用、三角面、贴图显存和关键帧，逐步执行 glTF Transform 的优化步骤，每一步都能在模型上预览、与原件对比、撤销，最后导出（可选 Meshopt/Draco 压缩）。名称、PBR、节点 TRS、贴图替换是同一份修订配方的输入。

P0：模型画布、优化流水线（一键步骤 + 阶段栈 + 前后对比）、导出。P1：贴图清单与替换、节点 TRS、动画片段播放、完整报告。P2：资产库中的打开/新建/删除/恢复。

## 首次使用
空态中心是“打开模型”：选择 GLB、glTF 与其 .bin/贴图（可多选）、ZIP，或直接拖入画布；也可“载入风机样例”。不需要先建工程。导入在服务端解码 Draco/Meshopt、合并外部资源，得到规范 GLB 原件；导入说明（例如“Draco 已解码”）以提示显示。默认打开“优化”检查器，第一屏即可点“剪除/去重/焊接…”。

## 继续上次工作
完整工作副本自动保存：原件/阶段引用、修订配方（含未完成数值、JSON、TRS 文本）、流水线步骤与每步报告、各步骤参数草稿、当前预览阶段、相机、动画位置、导出压缩方式与备注。刷新后回到同一阶段的预览；动画不自动播放。

## 导入恢复
资产库提供“打开模型 / 导入工程或恢复稿 / 新建 / 删除当前”。完整工程是 ZIP（project.json + 原件、每个阶段与替换贴图，按 SHA-256 校验），导入时只上传服务端缺少的资源，并创建新文档；0.8.x JSON 工程与恢复稿继续可导入。缺少资源时可补齐同一 hash 的文件。

## 空间关系
- 主工作区：全幅浅色三维画布，模型始终可转动；不被卡片框住。
- 画布右上：阶段条（原件 › 修订 › 剪除 › 焊接 …），点哪一段就预览哪一段，旁边是适配与检查器开关。阶段条就是“前后对比”的空间入口。
- 画布左侧：上下文工具轨（优化、材质、节点、贴图、动画、报告 | 备注）。
- 画布右侧：可收起的浮动检查器。优化页是一张技术表：步骤行（图标、名称、说明、内联参数、运行），下方是阶段栈（每步大小变化、耗时、说明、移除），再下是原件 → 当前的对比表；底部交付区放“应用修订”、导出压缩选择与导出按钮。
- 底部：材质色板带（材质页）、动画走带（有动画时）与读数行（绘制调用 · 三角面 · 文件大小）。
- 左上：资产库入口、可编辑文件名与安静的保存状态。

375px：画布在上（60svh），工具轨在画布左侧，检查器排到画布下方自然滚动，阶段条横向滚动，页面不横向溢出。

## 视觉
白灰背景利于判断形状与贴图；焦糖色只用于当前选择、变更点与待更新标记；数值使用等宽数字。正负变化用文字符号（−12%）而非仅颜色。与 Circuit 的底部仪表台、Oasis 的纸张/文件菜单不同，本界面由模型空间、阶段条和技术检查器组织。

## 状态
加载、空态、上传进度、处理中（显示正在运行的步骤，仍可转动模型）、步骤失败（错误贴在流水线旁）、待更新（配方变化后阶段条标点）、缺资源、离线/草稿/冲突。WebGL 不可用时流水线、报告与导出仍可用。KTX2 贴图保留在文件中，预览以灰色占位并提示。

## 不变项
appId、registryName、storageKey `gltf-transform-v1`、数据库迁移不变；新字段在 0.8 文档恢复时取默认值。Viewport 只在 documentKey 变化时重建；打开资产库、切换检查器页、预览阶段不会重建画布。

# Agent-Reach 0.9.0 · 调研资料台

## 用户与主任务

做技术选型、行业调研或写作准备的人：从公开网页、GitHub、V2EX 收集一手材料，读原文、摘出能作为证据的句子、给每条来源下判断，最后交出带出处的调研报告。

P0 是**读一条来源并摘录证据**；P1 是**往资料夹里添加来源**（采集→收件区→收藏）；P2 是交付（Markdown 报告、原生结果、完整项目）和可选的模型概括。

## 空间关系

资料桌三栏，一张桌面上同时摊开“目录—原文—摘录夹”：

- **左：资料目录**（300px）。顶部是紧凑的采集条（渠道分段、动作、链接/关键词、采集按钮），采集结果先进入目录上方的“收件区”，勾选后收藏；下面是按审阅状态筛选的来源列表，每行显示标题、域名、渠道、摘录数和审阅色点。采集是往目录里加东西，所以紧挨目录，而不是占据首屏的深色搜索横幅。
- **中：原文阅读**（弹性宽度，正文限 72ch）。来源头部给出渠道/后端、标题、作者、采集时间与“打开原链接”；工具条放“摘录选中文字”、审阅状态分段控件和更多操作；正文是保留的采集原文（纯文本，不渲染远程 HTML）；正文下方是这条来源的判断笔记。
- **右：摘录夹**（340px），两页：「摘录」是当前来源的摘录草稿与已存摘录（琥珀色引文条）；「小结」是整份调研的研究小结，以及可选的 Floatboat 模型概括（勾选来源→生成→插入小结，明确标注未经核对）。

文件生命周期收进左上角的「调研」菜单（对话框）：新调研、打开示例、最近调研、导入（完整项目 / Agent-Reach 原生 JSON / 恢复稿）、导出完整项目、编辑原生 JSON、下载恢复稿、重试保存、删除。顶栏只剩：菜单按钮、可编辑的调研名、安静的保存状态、右侧唯一的交付按钮「导出报告」。没有项目下拉框和“新建/导入/项目”按钮组。

## 首次使用

空数据目录首次打开即是一份真实的示例调研「浏览器端 SQLite 持久化选型」：4 条由本工作台从公开来源采集的资料（sqlite.org 文档、Chrome 开发者博客、PowerSync 博客、sqlite/sqlite-wasm 仓库），6 条示范摘录、审阅状态和研究小结。目录、阅读、摘录夹和报告导出在首屏都有内容。采集条预填下一步“GitHub 搜索 wa-sqlite”，点一下即可真实采集。页面加载时不发出任何外部网络请求。

用户在示例上直接编辑即自动保存为一份调研；「调研 → 新调研」得到空白资料夹（空态提示从采集条开始，或导入原生 JSON）。

## 继续上次工作

自动保存恢复最近一次工作副本（服务器草稿 + 浏览器 IndexedDB 回退），包括采集条输入、收件区候选与勾选、每条来源独立的未完成摘录、未应用的原生 JSON、模型概括草稿与勾选来源。「调研」菜单的最近列表可切换到其它调研或本机草稿。

## 导入恢复

导入完整项目或恢复稿：总是创建新调研，保留 extra，旧的未完成采集只记入“导入记录”，不自动重放。导入 Agent-Reach 原生 JSON：新建调研，成功条目直接收藏，同时留在收件区。

## 视觉

纸白阅读面 #fffdf8 放在暖灰桌面 #f2f0ea 上；石墨正文；靛蓝 #3346a3 只用于主要操作与当前选中；琥珀用于摘录引文。目录密集（13px 元数据），正文舒展（16px / 1.75 行高，等宽仅用于代码段）。审阅状态：未核对灰、已核对绿、待跟进橙，均附文字。深色模式使用同一套 token。

## 窄屏（375px）

顶栏保留「调研」菜单、名称和导出；下方出现三段视图切换「目录 · 原文 · 摘录夹」，选中来源后自动切到“原文”。采集条、收件区、筛选、摘录、小结与模型概括在窄屏全部可达；页面不横向溢出，长链接断行。

## 关键状态

采集中（按钮禁用并显示进度文字）、上次采集未完成（保留查询，显式重试）、无结果、平台限流/人工验证/非公网地址/超限/非网页类型（各自的中文说明 + 错误代码 + 尝试记录）、待收藏、已收藏（收件区标“已在目录”）、重复跳过、未核对/已核对/待跟进、模型未连接（在概括按钮旁说明启动 Floatboat 并可重新检查）。

## 与相邻工作台的差异

DeerFlow 是研究进度与交付纸张；PageIndex 是章节目录与原页；Agent-Reach 是“采集—阅读—摘录”的资料桌，核心对象是来源原文与证据摘录，不是生成报告的流程编排。

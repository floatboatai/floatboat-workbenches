### 限制

- 输入数据随流水线保存，单个输入节点 600,000 字符、项目 900 KB（共享自动保存上限）；更大的文件会被明确拒绝，需先截取。
- 表格在检查器中最多渲染 500 行（下载得到完整结果）；没有虚拟滚动。
- 正则安全靠“静态拒绝嵌套量词 + Worker 5 秒超时”；超时会中断整次运行，其余未完成节点标为中断。
- 自动运行结果只在内存中；只有点击“运行”才把预览写入文件。
- 没有通用表达式/计算列（金额 = 数量 × 单价 之类），只能用模板生成文本列。
- AI 起草仅验证了 Host 离线状态卡；本轮**未**进行真实 Host LLM 调用。Floatboat 客户端导入源包**未验收**。

## 0.9.1 AI 起草修复（2026-10-30）

用户反馈：输入“销售数据分析”生成候选时报“筛选行·mode：选项无效”，整份候选被拒。原因是提示词只列出配置字段名、不列可选值，模型把 `filter.mode` 写成 `and`；AI 候选与正式文档共用严格校验，一处不合法即全部失败。

- 提示词由字段结构生成（`describeConfig`），列出每个字段的可选值、范围和默认值。
- AI 候选单独修正（`repairGeneratedFlow`）：大小写与同义写法（and→all、>=→gte、descending→desc 等）、越界数值、单值写成列表、错误端口名（节点只有一个端口时）、缺失位置与标识；无法识别的值回到默认值；不支持的节点、无法对上的连线和写错的配置字段被移除或忽略。每处修正列在候选下，采用前可核对；修正结果仍经正式文档的严格校验。正式文档与自动保存的校验未放宽。
- 真实 Host 实测 gemini-3.8-flash：同一提示约五次有一次漏写闭合括号（JSON 不完整）。路由在 JSON 不完整时自动重新生成，最多 3 次；无法取出 JSON 时提示简化要求。
- 测试：28 项通过（新增：反馈场景与多种偏差的修正与运行结果、未知字段说明、无可用节点提示、提示词可选值完整、模型回复解析含漏括号实例）。`check` 通过。
- 真实浏览器（1440×900，Floatboat 已连接，模型 gemini-3.8-flash）：输入“销售数据分析”生成 6 节点候选（CSV 输入→筛选→分组汇总→排序→柱状图/表格预览），采用后自动运行“6 个节点全部成功”，控制台无错误。该次模型输出无需修正，候选下的修正说明列表未在浏览器中出现，由单元测试覆盖。

# Ray Optics 0.9.0：实时光路实验台

## 用户与主任务

主用户是光学课程的教师和学生，以及需要用二维几何光路解释一个装置的人。主任务：**在光学平台上放置/拖动光源与元件，实时看到光线、成像或观察者视角如何变化，读取探测器数值，并导出图像或场景**。旧版的“编辑→点计算→再看”被取消：光线随拖动实时重绘，导出随时可用。

## 首次使用、继续上次工作与导入恢复

- **首次使用**：空数据目录直接打开“凸透镜 · 平行光会聚”演示（平行光、凸透镜、探测器、标尺、标注），光线已经画出、探测器已有读数。用户无需先建项目，拖动透镜即可看到焦点移动。
- **示例库**：左上“实验”菜单 → 示例。16 个移植自上游画廊的场景（棱镜色散、反射棱镜、凹面镜、厚透镜、望远镜、全内反射、光栅分光、视深、蜃景、彩虹等）加 2 个原创场景（凹/凸面镜成像、光纤全内反射）。打开示例 = 新建一个实验，不覆盖当前实验；卡片显示上游作者与 Apache-2.0 来源。
- **继续上次工作**：自动保存完整工作副本；刷新后回到同一实验并立即重新追踪（光路是场景的函数，不需要旧的“计算结果”）。“实验”菜单 → 我的实验 列出已保存实验和本机恢复项。
- **导入恢复**：导入上游场景 JSON（version 1–5，旧版本由上游 versionUpdate 升级）或完整工程/恢复稿，均创建新实验。无法加载的输入保留在场景源码草稿中，可下载原件。

工作副本在首次修改后由自动保存建立；用户可见对象叫“实验”，内部仍存为 project。

## 空间关系

```
┌ 实验▾ │ 实验名称                                   保存状态（安静） ┐
├──────┬──────────────────────────────────────────────┬──────────────┤
│器材架 │ 模式[光线|延长线|成像|观察者] 彩色 质量 ↶↷ −+适配 PNG JSON │ 元件 / 场景 / 记录 │
│光源   │                                              │ 选中元件参数   │
│镜面   │              深色光学平台（原生画布）          │（上游 objBar）  │
│透镜…  │                                              │ 坐标/微调/删除 │
│遮光   ├──────────────────────────────────────────────┤              │
│测量   │ 读数条：追踪状态·光线段数·探测器 P/F⊥/F∥ ·警告  │              │
└──────┴──────────────────────────────────────────────┴──────────────┘
```

- **主工作区**：原生画布占据中央最大面积，1440×900 下约 880×640。
- **上下文工具**：视图模式、波长彩色、质量、撤销/重做、缩放、导出 PNG/场景 JSON 放在画布正上方的平台工具条——它们都直接作用于这块画布。
- **器材架**：左侧纵向，按上游分类（光源 / 镜面 / 透镜与玻璃 / 遮光与光栅 / 测量与标注）分组，共 27 种常用元件；点击即在视图中心放入一个预设元件并选中，随后在画布中拖动原生控制点调整形状。
- **读数条**：画布正下方固定高度，探测器读数与追踪状态在 1440×900 下无需滚动可见。
- **检查器**：右侧三页。元件页使用上游 `populateObjBar` 生成的参数（焦距、折射率、曲率半径、光栅线密度、发射角……）和上游 `getPropertySchema` 的控制点坐标；场景页是光线密度、网格、颜色映射、波长范围、最大交互深度和原生场景 JSON；记录页是实验笔记。
- **按需信息**：文件生命周期（示例、我的实验、新建、导入、导出完整工程/恢复稿、删除）全部在“实验”对话框里，不常驻页头。

## 视觉与密度

光学平台延续深色（#0b1119）以保证光线对比度；外围是暖白纸色与墨绿主色，读数用等宽数字。器材架用上游元件的几何符号而非彩色图标。检查器标签来自上游中文 i18n（HTML 标记转纯文本），保证术语与上游一致。保存状态是页头右侧小字，冲突/离线时才变色并给出“处理”入口。

## 关键状态

- 追踪：追踪中（分片计时器，显示已处理段数）/ 完成 / 达到质量上限（提示可提高质量）/ 已停止。拖动期间每次移动都会重启追踪，首个 50 ms 分片立即可见。
- 参数：合法输入立即应用到原生对象；不完整的数字（如“1.”、空）保存为草稿并标注“未应用”，刷新后仍在。
- 原生错误/警告（如未定义行为、亮度不一致）显示在读数条。
- 保存：idle/pending/saving/saved/draft/offline/conflict，冲突时提供导出恢复稿与打开服务器版本。

## 与相邻产品的结构差异

CircuitJS 以纵向元件架 + 电路/示波器 + 底部仪表为主，文件在“实验簿”；glTF 以全幅模型空间、底部材质带和浮动检查器为主。光路实验台的主区是可拖动的光学平台本身，模式/彩色/质量这些“看光的方式”贴在平台上沿，读数紧贴平台下沿，右侧是元件参数（光学元件参数多、需要常驻）。共享的只有“文件在菜单里”的惯例。

## 窄屏（375px）

顺序：页头 → 平台工具条（可横向滚动）→ 画布（固定 60vh，最小 340px）→ 读数条 → 器材架（横向分组滚动）→ 检查器。画布操作都有替代路径：元件列表选择、坐标数值、方向微调、删除按钮。

## 可访问性

所有按钮有可见文字或 aria-label；状态区 role=status；对话框用原生 `<dialog>`，Escape 关闭并把焦点还给“实验”按钮；画布可聚焦，方向键微调选中元件（Shift ×10）；`prefers-reduced-motion` 下无过渡动画。

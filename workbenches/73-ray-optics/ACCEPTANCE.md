## 浏览器流程（Playwright + Chrome for Testing 1243，1440×900 与 375×812）

1. **首次打开**：空数据目录直接显示凸透镜演示，光线已画出，读数条“光路已更新 42 段”，探测器 P=14.000 / F⊥=13.624 / F∥=−0.154；画布 900×702，读数条 y=814–880，1440×900 下无需滚动。
2. **实时拖动**：按住透镜拖动 8 步，每步读数条均为“光路已更新”，截图中光线随透镜位置重绘；松开后场景 JSON 中透镜 x 从 480 变为 384.5 并自动保存。
3. **检查器**：选中透镜显示上游 objBar 标题“理想透镜”与“焦距”；输入 320 立即生效（导出的 JSON focalLength=320）；输入 “-” 显示“未应用”，刷新后仍为 “-”。
4. **导出随时可用**：不需要计算步骤，PNG 下载文件头 `PNG`、900×702；场景 JSON 为 version 5、6 个对象、焦距 320。
5. **视图模式与色彩**：延长线 → `mode:"extended"`；成像 → `images`（540 段）；观察者 → 自动创建 `observer r=20`；波长色彩切换写入 `simulateColors:true`。亮度映射“线性值”显示 WebGL 层（2D 光层隐藏），此时导出的 PNG 有效（900×729）。
6. **器材架**：空白平台逐个放入 27 种元件，元件数逐一 +1，每个都显示上游标题与参数（如球面透镜 5 个参数 + 6 个控制点，渐变折射率圆 4 个参数），无页面错误。
7. **示例库**：打开“棱镜色散”（495 段，彩色色散）、“开普勒望远镜”（2,752 段）、“光纤 · 全内反射”（275 段，出射 12.875，漏光 0）、“棱镜与光栅分光”（1,528 段）均新建实验、对话框关闭并自动适配视图；卡片显示上游作者与 Apache-2.0。“下蜃景”渐变折射率示例标准质量 50,659 段；切到草图质量显示“已达质量上限 20,001 段”及提高质量提示。
8. **导入**：上游画廊原文件 `newtonian-telescope.json`（含 CropBox）→ 新实验，14 个对象，2,121 段；手写 version 2 场景（`laser`/`mirror`）经上游 versionUpdate 升级后新建实验并追踪；含未知属性的文件被拒绝（“第 1 个元件（平面镜）含不支持的属性 laserPower。”），当前实验未替换，原文放入场景页 JSON 草稿。
9. **自动保存契约**：首个 autosave POST 被挂起 2.5 s 时继续输入，刷新后笔记为完整的两段新文本；服务器提交后丢弃响应（`route.fetch` + `abort`）→ 状态“草稿已暂存本机，连接恢复后重试”，自动重试后“已自动保存”，项目数不变（同一 mutation 幂等）；无效原生 JSON 草稿刷新后仍在且场景未被替换，应用时提示“场景 JSON 语法错误…”；完整工程导出（含 quality=fine、笔记、未应用 JSON）后导入 → 项目数 +1，笔记与质量恢复。
10. **键盘与无障碍**：从元件列表选择后聚焦画布，Shift+→ 移动选中元件，Ctrl+Z 撤销回原坐标；实验对话框 Esc 关闭后焦点回到“实验”按钮；`prefers-reduced-motion` 下流程不变。
11. **375×812**：首屏与打开示例后 `scrollWidth=375`；顺序为页头 → 平台工具条（横向滚动）→ 画布 → 读数条 → 器材架 → 检查器；在窄屏放入探测器后读数条立即出现新行。

每个流程 pageerror / console error 为 0；唯一的 `ERR_CONNECTION_RESET` 来自注入的丢回执演练。截图 `docs/screenshots/ray-optics.png` 为 1440×900 的“光纤 · 全内反射”示例（选中纤芯，两只探测器读数可见）。

观察到并已修复的问题：首次实现沿用了“两个控制点不能重合”的旧规则，导致上游开普勒望远镜示例被拒——上游允许，已删除；彩虹示例光线密度超过旧上限 50，上限改为 1000（质量上限控制实际工作量）；窄屏下 `.app` 网格列被内容撑宽到 652 px，改为 `minmax(0,1fr)`；新增元件后元件列表延迟 250 ms 才更新，结构性操作改为立即提交；场景加载失败时读数条仍显示“已更新 0 段”，改为错误状态；示例在宽画布上偏小，打开示例与导入后自动适配一次。

## 结构审查（与功能验收分开）

主任务（放置/拖动 → 实时光路 → 读数 → 导出）全部发生在光学平台周围：视图模式、波长色彩、质量与导出在画布上沿，读数条贴画布下沿，参数检查器常驻右侧；文件生命周期（示例、我的实验、导入导出、删除）只在“实验”对话框，页头只有实验名称与安静的保存状态，不再有项目下拉/新建/导入横条。首次使用无需建项目。与 CircuitJS（纵向元件架 + 电路/示波器 + 底部仪表、文件在实验簿）和 glTF（全幅模型空间 + 浮动检查器）对照：共享“文件在菜单里”的惯例，但光路台的空间是“器材架 | 平台 + 读数 | 参数”三段，参数常驻是因为光学元件参数多且与光路同时调整。1440 与 375 截图已审阅。限制：器材架在 1440×900 下最后一项需滚动；示例自动适配以包含所有控制点为界，部分画廊场景留白较多。

## 仍然限制

- 背景图片场景、WebGPU/primitive 引擎、模块定义编辑界面、颜色/线型样式编辑未开放；画布“点击绘制”新建改为器材架预设 + 拖动控制点。
- 非标准亮度映射依赖 WebGL `OES_texture_float`；不可用时由上游回退为标准映射并给出提示（本机 GPU 已验证可用）。
- 每次重绘受质量上限约束，超大场景在草图/标准质量下为部分光路（有明确提示，导出 PNG 时说明）。
- 共享 `autosave-client.ts` 在切换/导入编辑过的文档时可能弹出“本机缓存尚未修复”确认（另一代理修复中），测试中自动确认。
- Floatboat 客户端导入未实测（hostImport=unverified）。

# 演示编排室需求与验收（0.9.0）

## 主流程

选版式 → 在舞台上放置与编辑富文本、图片、表格、图表、形状 → 套用品牌主题与画面比例 → 写演讲备注 → 导出原生 PPTX。项目 JSON 可导出并作为新文稿导入。AI 大纲为次要功能，先预览、确认后采用。

## 功能要求

1. 10 种版式以幻灯片母版导出，文本占位绑定 PPT 占位符；切换版式迁移占位。
2. 富文本段落 + 文字片段：加粗、斜体、下划线、颜色（主题角色或自定义）、http(s)/mailto 链接、项目符号、三级缩进。
3. 图片存为本应用媒体（SQLite，按 SHA-256 去重）；文稿只保存媒体 ID；导出 PPTX 与项目 JSON 时内嵌图片。
4. 表格 1–20 行 × 1–10 列；图表 1–8 个系列 × 1–24 个分类，类型柱形/折线/面积/饼图/环形。
5. 舞台选择、拖动、缩放、吸附、键盘微移、层级、复制/粘贴、删除、撤销/重做（拖动与连续输入合并）。
6. 主题六色角色、标题/正文字体、16:9（13.33×7.5 in）/16:10（12×7.5 in）/4:3（10×7.5 in）。
7. 演讲备注写入 PPTX 备注页；隐藏页写入 `show="0"`。

## 边界与校验

- 1–80 页，每页最多 40 个元素；单文本框 60 段、6000 字；备注 8000 字；字体名 60 字且不能含 `;"<>{}`。
- 未完成输入（图表格不是数字、字体名为空、链接格式不对、引用的图片不在媒体库）保存为草稿，正式模型不变，导出给出具体原因。
- 图片：原始文件 ≤ 30 MB；入库 ≤ 1.4 MB、长边 ≤ 2400 px（浏览器内自动缩放/转 JPEG，含透明度时保留 PNG）；服务端按文件头识别 PNG/JPEG/GIF 并读取真实尺寸。
- 项目 JSON 导入 ≤ 60 MB；0.3.0 旧格式（标题/页眉/要点/备注 + ember/ink/paper 主题）确定性迁移为“标题 + 内容”版式；数据库中的旧项目读取时同样迁移，原表与迁移文件不变，新增 `0004_media.sql`。

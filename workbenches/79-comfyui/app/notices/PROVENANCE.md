## Bundled node definition snapshot

`src/contracts/core-nodes-data.ts` is generated by `tools/make-snapshot.mjs` from the `/object_info` response of an unmodified ComfyUI **v0.43.0** server (commit `426f5eea52a7ece1dd599fff4cb6cd1f352ddd24`) started on CPU without any model files. It holds interface metadata only — node names, display names, categories, input/output types, parameter limits and tooltips for the core nodes (`nodes.py` plus selected `comfy_extras` modules). It contains no ComfyUI source code and no model weights. File-backed lists (checkpoints, LoRAs, …) were empty on that server and are filled with clearly generic example names so the offline demo graph is complete; real lists always come from the user's own server after connecting. Upstream attributes: ComfyUI is Copyright (C) Comfy Org / comfyanonymous, GPL-3.0; only facts about its public interface are reproduced.

## ComfyUI protocol

The client talks to the user's own ComfyUI through its public HTTP/WebSocket API (`/object_info`, `/system_stats`, `/prompt`, `/queue`, `/interrupt`, `/history`, `/view`, `/upload/image`, `/ws`). The protocol was learned from the published `openapi.yaml`, `server.py`/`execution.py` behaviour and by observing a real v0.43.0 server (message sequences, error bodies). No upstream code was copied; the mock server in `tests/support/mock-comfy.ts` is an independent implementation used only for tests and acceptance.

ComfyUI itself is never distributed, bundled or started by this workbench.

# ComfyUI 工作台 需求

目标：ComfyUI 节点工作流的完整节点编辑，然后在用户自有的 ComfyUI 服务上运行，并把产物与可复现参数留在文稿旁。

## 用户决定（逐条落实）

- **完整节点编辑**：核心是节点图编辑器（MIT `@comfyorg/litegraph` 画布），运行是其后的一步。
- **许可证 MIT**：工作台不含任何 GPL 代码（不含 ComfyUI、ComfyUI_frontend、comfyui-frontend-types）。边界见 `notices/PROVENANCE.md`。
- **先不接真实服务**：验收使用按官方 API 行为编写的模拟服务（`tests/support/mock-comfy.ts`）；真实生成记为未验证。

## 必须提供

1. 节点画布：双击搜索与分类节点库加节点；按类型着色并做类型检查的插槽连接；按节点定义生成的控件（INT/FLOAT 范围与步长、STRING 单行/多行、COMBO、BOOLEAN、seed 的“生成后控制”固定/递增/递减/随机）；Reroute、Primitive、Note、分组、折叠、绕过/静音、复制粘贴、撤销重做、多选、缩放平移适合窗口、小地图；控件输入口可接线。
2. 节点定义：连接服务后用其 `/object_info`（含自定义节点）；未连接用内置 ComfyUI v0.43.0 核心节点快照。含未知节点的工作流以“缺失节点”占位框保留全部数据。
3. 格式：导入/导出 ComfyUI 界面工作流 JSON（含分组、连线、`extra.ds`）；导入 API 提示词 JSON；导出 API 格式（穿过 Reroute/Primitive，正确跳过静音与绕过）；导入带 `workflow`/`prompt` 元数据的 PNG。导入永远新建文稿。
4. 离线校验：缺失必填输入、类型不符、未知节点、无输出节点、范围/枚举；显示在节点上和问题列表里。
5. 运行：应用内连接设置（地址、可选请求头令牌，令牌只在服务进程内存，可选“记住”存本机库，永不导出）；检查连接；排队；经 WebSocket 的节点进度与总进度；队列查看/取消/中断；服务端 `node_errors` 映射回节点；运行记录。只在用户点击连接/运行时访问网络；请求经应用自己的服务端转发，仅限用户配置的地址。
6. 产物：每个文稿的运行图库（后端存储，单图 ≤ 32 MB，每文稿 ≤ 60 次运行 / 256 MB，超限淘汰最旧），每次运行保存精确的提示词、种子与参数；“载入这次的工作流”为新文稿；2–4 张对比；下载含元数据的 PNG 与 ZIP。
7. 示例：SDXL 文生图（首屏），另有图生图、放大、LoRA、局部重绘、ControlNet 模板（仅核心节点）。
8. 结构与窄屏：见 `DESIGN.md`。

## 自动保存

完整工作副本（含视口）持久化；导入对话框中未完成的 JSON 以草稿保存；导入创建新文稿；延迟保存期间继续输入不丢；响应丢失后重试幂等。运行记录与图片不属于可编辑工作副本，存于独立表（迁移 `0004_comfy_runs.sql`），随文稿删除而清除。

## 限制

- 真实生成未验证（无模型、无真实服务的验收）。
- 子图（Subgraph）原样保留但不展开转换。
- WebP/FLAC 等其它元数据格式的导入未支持。
- 工作流 JSON 超过 880 KB 不能作为一个文稿保存（给出明确提示）。
- 已安装但已被 npm 标记弃用的 litegraph 0.17.2 固定使用，不随上游升级。

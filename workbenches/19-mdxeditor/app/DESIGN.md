# 文档审阅台设计

用户是维护教程、产品说明和发布说明的作者。主任务是在正文与源文之间写作，以固定的审阅基线核对本轮修改，并记录尚未解决的意见。

首屏以文档为主体：顶部是小型文件操作条；文档标题、审阅状态与三种视图构成第二层；宽正文与右侧连续审阅边栏共同组成编辑桌。基线条明确“左：比较基线 / 右：当前稿”，差异模式使用 MDXEditor 原生并列差异视图。没有导航文件夹、仪表盘或统计卡。

采用浅纸灰背景、深海军蓝标题、青绿色当前态；细网格线分隔文档区和审阅边栏，珊瑚色用于未解决意见。正文使用系统中西文字体，标题衬线与技术源文等宽字体区分阅读和代码。桌面编辑区正文最大宽 850px，边栏 290px；工具密度紧凑，正文保留阅读节奏。深色模式遵循 Host 主题与系统偏好。

主状态：加载、可编辑、等待自动保存、已保存、仅草稿、离线、冲突、源文不支持渲染、无差异、待处理/已处理意见。错误源文保留在原生源文编辑器，不替换成旧正文；离线与冲突提供恢复导出和服务器版本入口。保存确认不会重建编辑器。

375px 下工具栏换行，文件菜单收纳操作，正文与审阅边栏顺序排列；差异栏横向滚动限于编辑器内部，左右标识保留。所有操作可用键盘、可见焦点、具名控件，无必要动画，reduced-motion 不引入位移。

与 Tiptap 的单张纸写作区别：固定基线与差异是一级任务；与 BlockNote 的资料夹区别：一个 Markdown 文稿及其审阅记录是核心，不引入块树导航。

实施与验证顺序：模型与导入边界 → 原生编辑及三视图 → 完整工作副本自动保存 → 本地测试与 Chrome 真实输入/导出 → 375px、深色、恢复故障与截图 → 打包。

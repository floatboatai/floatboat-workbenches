# 交付复核台

用户：需要把资料整理、人工确认和最终交付分开的项目负责人。主任务是判断一份资料可否交付，而不是聊天或设计任意节点图。

空间：顶部紧凑项目条；横向三站执行路径连接「整理资料 → 人工复核 → 交付记录」；下部左右两张纸质作业区，输入始终留在左边，右边承载当前复核卡或最终回执；底部横向运行账本与检查点。不是通用仪表盘、统计卡或固定导航侧栏。

视觉：暖灰操作台、白色纸面、深墨绿执行线与陶土色人工复核状态。标题使用系统衬线字族，流程编号与时间采用等宽数字，字段使用系统中文无衬线。紧凑工具条与宽松正文形成不同密度。状态另有可读文字和图形，颜色不单独传达意义。

状态：项目自动保存和流程运行独立显示。运行可能为未开始、执行中、待复核、已交付、已退回、失败、进程中断或已取消。模型断开时显示可操作原因；填写资料仍可执行真实 LangGraph。正在执行的输入是不可变快照，新的编辑保留给下一轮。复核文本单独作为草稿保存，失效响应不能覆盖新编辑。

窄屏：项目工具换行，流程压缩为纵向短轨，输入与复核按顺序堆叠；运行账本局部滚动，不产生页面溢出。原生按钮和表单，清晰焦点、跳转到主区链接，禁用非必要动画并支持 reduced-motion。

验收：真实 prepare/interrupt/resume/deliver 与 SQLite 重开；人工修改不被新结果覆盖；自动保存、无效 JSON 草稿、冲突和导入新项目；375/1440 视口、键盘、错误恢复、截图与 JSON/Markdown 导出。

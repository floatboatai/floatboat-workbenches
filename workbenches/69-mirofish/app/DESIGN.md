# 群体推演台

## 用户与主任务

政策研究、公关与社区工作者，想在决策公布前看“各方会怎么说、舆论会怎么走”。主任务沿 MiroFish 自己的流程走：种子资料 → 实体与关系图谱 → 智能体人设 → 推演参数与事件 → 运行 → 观察舆情与立场变化 → 报告。工作对象是“一份推演”（问题、资料、图谱、人设、参数、运行记录与报告），内部存为 project，界面不出现“项目”。

## 首屏与路径

- **首次使用**：自动打开原创示例“滨河市老城区低排放区试行”（4 份资料、17 实体 24 关系、26 个智能体、3 次事件注入、已完成的 36 轮推演与规则报告），首屏落在“观察”阶段，直接看到舆情构成、平均立场、群体走势、热力条与时间线。
- **从零开始**：推演档案 → 新建空白推演，进入“资料”阶段的空态，主操作“添加资料文件”就在空白处；粘贴正文也可。之后每个阶段的空态都给出下一步按钮。
- **继续上次工作**：打开即恢复上次的推演与所在阶段（阶段、选中实体/智能体、轮次筛选都在自动保存的工作副本里）。
- **导入与恢复**：推演档案里导入 `.mirofish.json`、恢复稿、0.5 复核工程或 MiroFish 原生结果，一律新建一份推演，不覆盖当前；资料文件（TXT/MD/HTML/CSV/PDF）加入当前推演。工作副本在新建、示例、导入时创建，编辑即自动保存；冲突/离线时保存状态旁出现“重试保存 / 打开服务器版本 / 下载恢复稿”。

## 空间关系

- **一行文件条**（深墨色）：推演档案按钮 · 推演名称 · 安静的保存状态 · 三个通道状态胶囊（本地引擎 / MiroFish / 模型）。文件生命周期全部在推演档案对话框中。
- **六段流程带**：每段显示编号、名称和当前内容摘要（“17 实体 · 24 关系”“推演 #1 · 232 动作”），已完成的段编号填色；窄屏横向滚动并始终把当前段滚入视野。
- **阶段工作区**，各自按对象组织：
  - 资料：问题与资料目录 | 纸面正文编辑 | 议题要点与“从资料抽取图谱”。
  - 图谱：点阵画布占主区（拖动、连线模式、重新布局、列表视图）| 右侧检查器（实体/关系/类型统计）。
  - 人设：生成工具（规则 / 可选模型）| 名册表（立场条、活跃、影响）| 逐个智能体编辑（滑杆、24 小时活跃时段、人设文本）。
  - 推演：参数网格与事件注入时间轴 | 引擎面板（本地推演 / MiroFish 后端两个标签）与运行记录。
  - 观察：运行选择与 KPI 条 + 导出 | 宽幅舆情构成（可点选轮次，事件编号标记）| 平均立场与极化、群体走势并排 | 智能体立场热力条（点行筛选时间线）| 时间线（轮次/角色/动作筛选，分页）。
  - 报告：生成与模型深化、导出、研究者备注 | 纸面预览 / Markdown 编辑。
- 主操作贴着对象：抽取按钮在资料旁，连线在画布工具条，开始推演在引擎面板，导出数据在 KPI 条旁，导出报告在报告旁。MiroFish 与模型的状态、启动方式、“重新检查”都在各自按钮旁。

## 视觉语言

暖纸色桌面（#efece3）+ 深墨文件条，强调“推演沙盘”而非市场仪表盘。立场使用一套发散色：反对朱红 #bf4f2e、中立灰米 #cfc8b8、支持青绿 #2b7a84，图谱节点底色、热力条、时间线左侧色条、名册立场条共用；实体类型用 8 色描边区分。数字使用等宽数字；资料正文用宋体纸面，强调这是“读材料”。密度中等偏高，面板 8px 圆角、细边框。

## 关键状态

- 保存：idle/pending/saving/saved/draft/offline/conflict 原文显示在文件条；未完成输入（实体名为空、轮次 0）保存为草稿，运行按钮旁写明需要修正的第一处。
- 推演中：流程带右侧显示“正在推演…”，按钮锁定；结果载入失败给出原因与“重试”。
- 本地运行记录保存完整输入，换机/导入后按输入重新生成并核对指纹；导入结果的立场以“词典估计”警示条标出。
- 通道：MiroFish 未连接时显示地址、启动四步与“重新检查”；模型未连接时按钮禁用并在旁说明，规则人设/规则报告不受影响。
- 报告与当前运行不一致时显示提示，HTML 附图导出与模型深化暂停；切回报告对应的运行或重新生成后恢复。历史报告标题与问题取自运行快照。

## 窄屏（375px）

单列：文件条两行（通道胶囊换行）；流程带横滑；各阶段面板按“工具 → 主对象 → 检查器”顺序堆叠；图表卡片内部横向滚动，正文页面不横向溢出；推演档案为全宽对话框，Escape 关闭并把焦点还给按钮。

## 与相邻工作台的差异

- React Flow（节点 IDE、暗色画布、左侧节点库）：同为画布，但这里图谱只是六段流程中的一段，主区随阶段切换，画布是浅色点阵并以立场着色；运行与结果在独立阶段而非底部控制台。
- Vega-Lite（图表实验台 + 规格检查器 + 数据窗）：都有图表，但这里图表是推演结果的固定观察面板，配合热力条与原生动作时间线，不提供规格编辑。
- 0.5 版 MiroFish（海军蓝角色轨 + 动作复核）：去掉项目选择器与“新建/导入/工程”按钮组；复核动作时间线并入“观察”阶段，新增资料、图谱、人设、推演与报告阶段。

## 2026-10-29 结构审查

实际打开并对照当前仓库的 `docs/screenshots/vega-lite.png` 与 `docs/screenshots/deeptutor.png`，没有仅以配色作区分：

| 维度 | Vega-Lite 实际截图 | DeepTutor 实际截图 | MiroFish 实际页面 |
| --- | --- | --- | --- |
| 主区 | 图表约占左侧三分之二，数据窗在下，规格在右 | 讲义与答题区并排 | 六阶段共用工作区，观察阶段以宽图、趋势对照、热力条和时间线向下展开 |
| 工具位置 | 图表旁导出，规格旁格式化 | 题号横轨、答案附近核对 | 抽取、生成、运行、导出分别贴近各阶段对象 |
| 文件生命周期 | 顶部文件菜单 | 顶部课程菜单 | 推演档案模态面板，无项目选择器与立即保存主按钮 |
| 窄屏路径 | 本次只对照既有桌面截图，未重测该应用 | 本次只对照既有桌面截图，未重测该应用 | 六阶段横轨可滚动，主区单列，文件菜单与必要操作保留 |

MiroFish 的 1440×1000、375×1000 页面实际验证六阶段无正文横向溢出；图表在自身容器内横向滚动。空白推演和有内容示例均走通主任务；375px 覆盖新建、打开已保存、导入推演/恢复稿、刷新恢复、运行与 Markdown 下载。推演档案 Escape 关闭并把焦点还给触发按钮，后台保存不阻止继续输入。

功能验收单列于 `ACCEPTANCE.md`；结构审查结论为 `passed`。真实截图为 `docs/screenshots/mirofish.png`，窄屏与其余证据保留于工作区 archive。无屏幕阅读器完整测试；图谱列表是实体/关系检查器的键盘替代入口，触控拖动与所有图表键盘交互未作为本次验收通过项。

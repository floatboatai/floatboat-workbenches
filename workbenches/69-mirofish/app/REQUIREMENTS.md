# MiroFish 群体推演台

把 MiroFish 的推演流程放进一个工作台：种子资料 → 实体与关系图谱（可编辑）→ 智能体人设 → 推演参数与事件注入 → 运行 → 舆情与立场时间线 → 报告。

- 无外部服务、无 Floatboat Host 时完整可用：规则抽取图谱、规则人设、Node 内确定性推演（有界信任意见动力学 + 推荐流 + 事件注入，随机种子可复现，5 种子稳健性检验）、可视化、规则报告与 CSV/JSONL/HTML/Markdown 导出。
- 资料接住 TXT/MD/HTML/CSV/JSON/PDF（含 GB18030），合计 20 万字；MiroFish 原生结果（detail/actions 响应、actions.jsonl）最大 40MB / 10 万条，分片上传，按内容寻址存储。
- 可选 Floatboat 模型：改写人设、深化报告；输出校验后作为建议，确认后才写入。未连接时禁用并说明，规则路径不受影响。
- 可选官方 MiroFish 后端：健康检查、启动方式、已准备模拟的启动/停止/状态核对、读取结果到运行记录；命令先持久化，未知回执不重放。
- 自动保存完整工作副本（阶段与选择、未完成输入）；导入一律新建推演；0.5 复核工程可读并转为只读导入运行。
- 不发起真实 Host/LLM 调用做验收；Host 通道以 mock 合同测试，MiroFish 通道以本地 HTTP 合同测试。

## 收尾验收要求

- 新建空白推演，从资料导入到报告下载不依赖外部服务；“离线”指本地工作台 HTTP/SQLite 仍运行、Host 与官方模拟服务不可用，不承诺浏览器脱离本地服务运行。
- 自动保存须验证延迟回执期间继续输入、提交后丢失响应的同一 mutation 重试、无效轮次草稿刷新恢复、跨标签页冲突保护、全新离线工作副本找回；导入推演和恢复稿不得覆盖来源记录。
- HTML 的报告和附图须属于同一次运行。编辑当前问题后，对历史运行生成报告仍使用该次运行保存的问题与话题；切换运行后须重新生成报告或切回原运行才能导出附图。
- PDF 不按页数静默截断；超过文字容量须明确拒绝并提示摘取章节。扫描件需要先做 OCR，密码文件需要先解密。
- 桌面 1440px 与窄屏 375px分别检查六阶段、文件菜单、主流程和错误恢复。只使用独立无头 Chrome，不连接用户日常浏览器。
- 文档定稿后再打包，旧同版本包先归档。验包逐文件比对 `application/` 与 `app/`，资源绑定允许模板规范化；包不含预览数据库、凭据或 node_modules。

## 容量与适用范围

最多 12 份资料、合计 20 万字符，单文件 60MB；160 实体、600 关系、200 智能体、240 轮、40 事件、8 次运行。保存模型仍受 900KB 限制，大量资料和多份输入快照可能先达到保存上限；失败时保留工作副本并提供恢复稿。原生结果最大 40MB / 10 万条，独立存放于结果库。

本地推演是规则与概率模型，文本由模板生成；规则抽取以中文资料为主，不提供 OCR、模型级语义理解或现实预测承诺。真实 Host、OASIS/Zep 模拟与 Floatboat 客户端导入另行验收。

## 未覆盖与产品边界

- 未启动完整官方 Docling Serve 服务，未验证其 live async 往返；当前只有官方合同测试，真实执行证据来自 Docling core。连接器启动说明可复现，但环境安装未在本次重新执行。
- 不进行 PDF/DOCX 文件上传、页面图像渲染、OCR、视觉模型或 Host 模型调用。Host 实际状态为 `HOST_NOT_CONNECTED`。
- Floatboat 客户端包导入、服务环境变量配置与账号授权尚未验收。源包导出成功不等于客户端已安装。
- 目前只在 JSON 校订层修改文本、类型、表格文本和同级顺序；不编辑行列拓扑、图片、公式或跨父级移动。JSON 解析后的数值遵循 JavaScript Number 精度，不承诺字节保真。
- `.review.json` 包含解析原件和校订；转换 HTML 原文件及上游任务保存在应用数据资源，不包含在该业务导出中。数据默认不进入源码包。

## 容量恢复回归（2026-10-27）

复现：598786 字节的合法原 DoclingDocument 加校订构成 799000 字节正式项目；再填写合法的 3000 字符备注后达到 802042 字节。服务器可存为 draft，但旧的 `restoreDraftData=validateReview` 会以正式 800 KB 限额拒绝恢复。

修复保持原文 600 KB / 正式模型 800 KB；独立恢复 decoder 保留全部结构、引用和字段约束，允许工作稿到 1.2 MB。UI 对 title/data/extra 的完整工作副本施加 1.85 MB 总量限制，超过容量时保持原输入。便携 `.review.json` 导入与导出支持同样的工作稿范围；合法文件直接校验并作为新文档打开，避免在旧稿内重复保存大段 raw。

新增 3 项自动化测试，当前共 **23/23 通过**：实际文件 SQLite 保存 draft、关闭/重开数据库后恢复、原正式项目保持、review 往返、精简后恢复正式保存；恢复 decoder 边界与不合法引用/字段/原件；总请求预算。

Chrome 5 条针对性流程通过：
1. 799 KB 正式项目继续编辑为 802 KB 草稿，刷新完整恢复备注，正式项目保持原值。
2. 超 800 KB 的 `.review.json` 实际下载后通过文件输入重新导入，得到独立文档 ID，刷新恢复一致。
3. 1.199 MB 工作稿文件导入成功；再填备注越过 1.2 MB 时拒绝本次修改。
4. 大工作稿加 630 KB 未应用 raw 输入（工作副本约 1.829 MB）刷新恢复；增加到越过 1.85 MB 时保留原来的 630 KB 输入。
5. 捕获所有真实自动保存 POST，最大 **1829220 字节**，全部小于 1950000；无 pageerror。

本修复未修改共享保存蓝图、迁移、截图或其他工作台；无需重复既有转换/视觉验收。

# Docling 0.9.0 产品要求

用户是需要将真实文档转为可检索内容、并核对抽取结果的资料整理者。工作对象是“一份文档及其校订”，不要求用户先创建项目。

## 主流程

1. 空数据首屏可打开内置五页报告；从转换面板选择 PDF、DOCX、HTML 或 Markdown，无外部服务也能得到真实 DoclingDocument。
2. PDF 以原页图像和结构坐标框联动结构目录、校样稿与校订栏；其他本地格式提供原文段落/表格与源行号对照，不能把段落投影称为原页渲染。
3. 人工修改文本、类型、标题级别、表格单元格、同级阅读顺序、复核与备注；保留原始引用、原文及未知字段。
4. 导出校订 JSON、Markdown、独立 HTML、单表/全部表格 CSV，以及包含原文件的校对 ZIP。导入及采用 Serve 结果始终新建文档，保留原项目。
5. 自动保存完整工作副本，包括未应用 JSON 和转换设置。延迟响应不得覆盖新输入；丢响应重试复用 mutation ID；离线、草稿、冲突均不得冒充保存成功。恢复副本可另建文档。
6. 文档生命周期放在文档菜单；375px 通过四个视图分页访问主操作。面板支持 Escape、焦点返回、Tab 循环，编辑和后台保存不抢焦点。

## 可选官方服务

独立 Docling Serve 支持官方文件格式与 OCR/版面/表格选项。转换操作附近显示可用状态、启动方式和重新检查；未运行时仍可选择本地解析。提交前持久化输入与本地操作 ID；不确定提交不自动重交，已有任务可关联、暂停与恢复跟踪。官方推理与本地启发式解析在界面上分别标注。

## 数据约束

原文件 ≤64 MiB，结构 JSON ≤48 MiB，每类结构数组 ≤50,000 项，每表 ≤100,000 格，层级 ≤64。SHA-256 原件/结构资源与小型校订工作副本分离。正式校订模型 ≤800,000 字节，恢复工作稿 ≤1,200,000 字节，title/data/extra 合计 ≤1,850,000 字节。旧 0.4 嵌入原件的项目可读取并迁移至内容引用；原迁移不重写。

## 验收边界

Node 22 check/test/package，1440×900 与 375×812 独立无头 Chrome、空数据、本地四格式、框选/片段校订、下载与 ZIP/JSON 导入、自动保存异常及冲突恢复。Serve 用明确标注的本机 fixture 验证；不得真实 Host/LLM 调用或用外网服务做验收。完整官方 Serve/OCR、最大尺寸性能、Floatboat 客户端安装均单列为未测。

功能验收与结构审查分开记录，详见 ACCEPTANCE.md 和 DESIGN.md。最终文档必须先于打包完成；验包时逐文件比对 application 与 app 源码，manifest 仅允许模板资源规范化。

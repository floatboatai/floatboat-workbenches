# Autosave integration contract

Copy autosave-contracts.ts to app/src/contracts/autosave.ts; autosave-server.ts to app/src/server/autosave.ts; autosave-cache.ts, autosave-client.ts and requests.ts to app/src/ui/. Append autosave-migration.sql as the next numbered migration. Do not overwrite applied migrations. Existing workspace.tsx, App.tsx, navigation and styles are owned by the product and remain unchanged during synchronization. The initializer can supply optional helpers in workspace.tsx for a new app; choose the product's file navigation separately.

Register `registerAutosaveRoutes(app, validate)` alongside existing API routes. Optional third argument is `AutosaveAdapter<T>` with synchronous get(id), create(title,data,id), update(id,title,data,revision), each returning Project<T> {id,title,data,revision,updatedAt}. create must use the supplied id, not generate a different id. For Excalidraw map existing boards to generic Project<{scene:string}> and supply GET /api/projects list/detail and DELETE /api/projects/:id aliases with revision validation; keep old API. Optional fourth argument `{verify: async(data)=>...}` performs required source validation BEFORE the SQL transaction (e.g. MusicXML original/XML correspondence). Drafts persist even when validation fails; the model changes only when valid.

Use `useWorkbenchState(seed,validate,title,{storageKey:'unique-slug',restoreDraftData?})` directly, or retain an existing app-owned `useProjects` wrapper. `restoreDraftData(raw:unknown):T` is called only when restoring a persisted working copy; it must enforce structure/types/size while allowing unfinished business values. Default is validate. Do not cast arbitrary JSON. The full working copy persists on the server, plus an IndexedDB fallback. Storage uses projects internally; user-facing navigation should use the product's working object and file lifecycle. Preserve all local recovery items when presenting the saved-copy list.

Existing API is retained. `open(id)`, `fresh()`, `replace(data,title,extra?)`, `remove()` now return Promise<boolean>. Await success before resetting local UI. `save(override?)` returns Promise<Project<T>|null>. `replace` starts a NEW project after flushing the old working copy; use for imports so autosave never silently overwrites the old project. loadEpoch/documentKey change only on document transitions, never when an autosave creates/updates a row. Replace editor keys based on current.id with documentKey.

Use `draft` / `setDraft` (Record<string,unknown>) for unapplied JSON, CSV, coordinate text, questionnaire answers and other transient user input. Decode each extra field by type before using it. Restore these from draft/documentKey, do not clear them whenever data object identity changes. Locally invalid data uses restoreDraftData; invalid raw inputs are saved as drafts, not misreported as applied model state.

Display autoState.message using role=status and explicit phases idle/pending/saving/saved/draft/offline/conflict. Background saves do not set busy or disable editing. Manual save can become an unobtrusive “立即保存” or retry action. Keep exportDraft for recovery and offer open(current.id) for server-version conflict resolution. Do not label draft/offline/conflict as saved successfully.

Validation: pause typing and confirm automatic POST, reload/preview restart restores; edit while a response is delayed and confirm newer text remains; reject one save then retry; simulate response lost AFTER server commits and confirm one project/idempotent mutation; invalid raw editor draft restores; existing project import creates new project; optimistic conflict never overwrites other content. Capture final screenshots after both autosave and product layout pass.

Local recovery uses IndexedDB copy+active-pointer transactions and a storageKey-isolated list. Unacknowledged local copies appear as local: items and replay the original mutation without changing the captured project revision. A new tab at the same browser origin can recover them; this is not cross-origin/preview-port/device recovery. Only claim local preservation when the IndexedDB transaction succeeds. Background save acknowledgements clear only errors owned by the save operation. Verify a brand-new offline draft can be switched away from, found in the list and resumed, and that a fresh tab cannot bypass a cached conflict.

An acknowledged fingerprint carries the authoritative receipt phase/message/time, including server-only asynchronous verification drafts. Cache it atomically with the copy; legacy caches without a receipt remain explicitly unconfirmed until an optimistic retry confirms their original revisions. A rapid edit/revert must restore both the receipt and IndexedDB content. Cache repair remains pending until success, retries manually/automatically/online, and protects unload/navigation; late callbacks must check the document epoch. Test cached B followed by revert A before debounce, async verification drafts, cache-write failure/retry, in-flight mutations, legacy acknowledgement retries and cached conflicts. An acknowledged save whose copy and receipt were cached in the same write leaves the client clean. Switching documents before the debounce fires, or right after a restored mutation loads, must not show the cache-repair warning. The warning must still appear when the IndexedDB write fails (`scripts/tests/autosave-client.test.mjs`).

# 按任务设计工作台

每个工作台先写清用户最常做的动作，再选择空间组织、信息密度和视觉语言。共享技术底座，分别设计产品界面。

| 工作台任务 | 默认设计起点 | 首屏重点 |
| --- | --- | --- |
| 自由白板 | 画布占据主要空间，文件导航可收起 | 直接绘图、保存状态、轻量工具条 |
| 资料与脑图 | 大纲与导图对照，输入与结构之间即时反馈 | 资料层级、节点关系、聚焦当前分支 |
| 单据与报告模板 | 纸张预览、字段面板与数据映射 | 版式、字段绑定、生成结果 |
| 文档写作 | 有阅读节奏的排版与上下文工具 | 正文、选区修改、版本差异 |
| 数据分析 | 表格与图表联动，强调数字和异常 | 数据范围、变换步骤、结果 |
| 流程编排 | 节点、连接、运行状态与日志 | 输入输出、当前节点、失败恢复 |
| 信息监测 | 时间线或变化队列 | 新变化、差异与后续动作 |

每个 `app/DESIGN.md` 记录：用户与主任务、首屏优先级、布局原型、独立的色彩/排版/密度选择、关键状态、窄屏方案，以及与相邻工作台有意义的差异。

功能相似时可以复用交互约定，但不能仅更换标题、图标、主题色就作为另一个产品设计。避免给所有项目强制套用固定侧栏、顶部统计卡和三栏卡片布局。

Vercel React Best Practices 用于加载、数据获取和渲染效率；Web Design Guidelines 用于语义、可访问性、状态和交互检查。它们不代替具体的产品视觉决策。

## 用户确认的方向

“按照每个产品应该有的风格来设计”。以真实工作方式决定空间和控件，自动保存是基础能力，主要按钮留给绘图、运行、应用、导出等业务动作。

| 产品 | 当前空间组织 |
| --- | --- |
| Excalidraw | 最小文件条、全幅原生画布、按需打开目录 |
| Markmap | 脑图主体、可收起的大纲、轻量整理工具 |
| React Flow | 节点 IDE、参数检查器、独立运行控制台 |
| SurveyJS | 三阶段表单流程、题目编排与答卷，不放宣传区 |
| Maker.js | 毫米图板、尺寸/孔位检查器、技术图纸输出 |
| SeqViz | 环图与线性序列联动、特征和审阅记录 |
| pdfme | DTP 页面轨、灰色粘贴板、右侧字段 |
| Tiptap | 窄正文、轻量格式工具、收纳文件操作 |
| PptxGenJS | 缩略图、黑色舞台、内容和演讲备注 |
| OpenSheetMusicDisplay | 宽谱面、声部/小节导航、校样批注 |
| farmOS-map | 地图主屏、编辑工具、分区与坐标登记 |
| Mermaid | 源码 IDE、行号和图形预览 |
| Swagger UI | 端点目录与原生 API 文档、按需规格编辑 |
| Vega-Lite | 图表实验台、规格检查器和数据窗 |
| Observable Plot | 数据观察报告、图表和原始数据 |
| Mirador | 左侧资料抽屉、双图光台、右侧复核账本 |

色彩、排版与密度跟随产品角色；截图审查同时检查首屏主任务、空间利用、窄屏流程和错误反馈。后续项目按其自己的领域做新的判断。
